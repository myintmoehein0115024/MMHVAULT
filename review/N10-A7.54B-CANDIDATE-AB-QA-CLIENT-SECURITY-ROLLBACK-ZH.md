### UI/会话安全细节

- 用户名规则为字母开头、4–20 字符，仅允许小写字母、数字和下划线。
- 绑定操作必须通过 Supabase Auth `getUser()` 的真实 UID 和当前登录会话 `getSession()` 同 UID 且已确认邮箱；服务器再核对对应密码及授权白名单。
- 两种操作必须使用**不同的** Cloudflare Turnstile action，切换操作会重新创建验证码，不混用验证码令牌。
- 用户名登录收到的短时访问/刷新令牌只在闭包内保留以验证结果，使用**非持久化 Supabase 客户端**向 Auth `getUser(jwt)` 核实回来的 UID 与之前绑定的 UID 严格一致；也复核当前已登录用户 UID。
- 不调用 Supabase `setSession`，不写 `localStorage` / `sessionStorage`，不把测试证明令牌交给 `app.html`；结束调用服务端 `logout?scope=local` 尝试回收短时证明会话，清空密码输入、重置验证码。注销为尽力操作，访问 JWT 可能仍持续至自然过期，不夸称即时全局失效。
- 此路径用于受控测试证明**身份映射**正确，不是对现有财务主站 session handoff 的完整正式上线验收。正式业务会话交接、OAuth 回跳与其他模块的完整回归仍需后续独立批准和验收。
- HTML 公开静态文件无任何真实账号 UID、邮箱或服务端私钥；公开 publishable key 与 Cloudflare sitekey 并非私钥。
