# MMHVAULT — N10-A7.51 管理员浏览器健康检查交接（无正式站修改）

日期：2026-10-29。用户提出“继续”，本阶段只进行正式 Edge 只读核验和独立本地 QA 工具创建，没有授权部署/开启登录或变更 GitHub main。

## 使用场景

N10-A7.50 已部署且仍关闭的正式 Edge `mmh-n10-a740-username` 有 `action='configuration_health'` 管理员限定路由，必须满足：
- 来源为 `https://mmhvault.com`；
- 实际 Supabase Auth 用户会话 Bearer JWT（平台 `verify_jwt=true`）；
- Edge 二次请求 Auth `/auth/v1/user`；
- 同一 UID 的 `public.mmh_is_admin()` 服务器端成员验证；
- 返回裸 JSON boolean `true/false`，不返回密钥或逐项配置。

普通下载的 `file://` HTML 无法在符合来源域 `mmhvault.com` 的上下文中请求 Edge。为了避免修改正式 GitHub main 或要求用户复制 JWT，选择**浏览器 bookmarklet 书签检查器**：一份独立的自包含 HTML 在用户本机打开，将经过审查的 JS 书签拖放至 Chrome 书签栏。用户在已登录的 `mmhvault.com/app.html` 点击书签后，在同源页面上执行检查，并用小型固定浮层只显示状态。

## 安全限制

- 检查工具不需要输入账号密码或 Secret，不保存 JWT，不接收用户粘贴 JWT，不发送到 ChatGPT/GitHub。
- 使用官方 Supabase UMD 客户端从用户当前站点会话取得 access token，只将 JWT 通过 HTTPS Authorization 头传到**同一生产 Supabase Edge**的健康路由，Header 使用公开 publishable key；`credentials:'omit'`，`cache:'no-store'`，`referrerPolicy:'no-referrer'`。
- 只发 `{"action":"configuration_health"}`，不读取或写入财务数据、UID 关联表、限流桶表。不会调整登录开关。
- 严格限制当前浏览器 `location.origin==='https://mmhvault.com'`；其他域名、未登录、无 Supabase SDK、无权限、错误响应、网络中断全部显示友好错误。
- 显示健康布尔结果不意味着 Turnstile Secret 已通过 Cloudflare 真正 Siteverify 或真实两账户登录已通过。
- 要求使用者只反馈“通过 true / 未通过 false / 无管理员权限 / 网络故障”，**不得发送密码、token、Secret 或控制台日志**。
- 书签工具只能在用户自己的受信任浏览器页面运行；不要在第三方页面运行、安装未知插件或截取凭据。

## 交付与本地模拟验证

生成独立 HTML：`MMHVAULT-N10-A7.51-Admin-Health-Bookmarklet.html`（通过当前聊天文件下载；**不上传 GitHub main**）。HTML 包含可拖动的 JavaScript 书签链接，以及本地复制书签地址备用操作。

使用 Node VM（全部模拟、无网络）完成 7 场景：
1. 管理员配置 `true` 显示通过；
2. 配置 `false` 显示未通过；
3. HTTP 403 识别为管理员授权失败；
4. 无用户 session 不发请求；
5. 错误域名不发请求；
6. 未加载 Supabase SDK 不发请求；
7. 网络故障显示失败。

同时静态检查 HTML 仅包含 1 个 `javascript:` 书签 URL，且不包含 `sb_secret_`、Turnstile/HMAC 私钥或密码字段。此前 N10-A7.50 的候选 CI 已检验真实 Edge 路由安全和旧登录关闭。

- **本阶段未从真实管理员浏览器向生产 Edge 发送健康请求**。因此当前不知道生产返回是 `true`、`false`、403 还是其他错误。
- **不要求用户提供或转发管理员 JWT**。必须在受控的正常浏览器会话里运行上述书签。
- 正式 `main`、`app.html`、DNS、财务业务数据库不变；正式登录开关仍为 `CODE_GATE_OPEN=false`，1970 年过期窗口和 `verify_jwt=true`。
