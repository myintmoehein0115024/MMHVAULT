## 本轮实际修改

1. `login.html`：用户名成功交换会话后，暂停原 `SIGNED_IN` 自动跳转监听，仅允许新流程通过远端 `getUser` 和本地 `getSession` 比对相同 UID，再走原 `verifiedRedirectV946`。
2. `js/mmhvault-n10-a7-40-username.js`：设置短时 handoff 标记，若 `setSession` 失败、UID 不匹配或安全跳转返回 false，局部退出；`finally` 恢复标记。用户密码不写入日志，不把业务数据上传到 Edge。
3. 前端域名收窄为 `https://mmhvault.com`，和 Edge 的 `Origin` 白名单保持一致，避免 `www` 站点误显示可用。
4. `review/N10-A7.40-PRODUCTION-EDGE-CANDIDATE-NEVER-DEPLOY.ts`：将登录请求的密码输入上限与前端统一为 128（**只限制已有账号登录入参，不改变新用户密码政策**）；公开 preflight 不再披露后端密钥配置状态。
5. `tests/n10-a7-41-username-handoff-mock.cjs`：纯内存开启假的前端 gate，模拟正常交接、跳转失败、远端 UID 不匹配、会话写入失败、服务端拒绝五条路径。**没有联络任何真实 Supabase、Turnstile 或账户**。
6. 原前端 `ENABLED=false`、`TURNSTILE_SITE_KEY=''`；Edge `CODE_GATE_OPEN=false`、过期窗口；生产数据库草案仍仅在审查目录。

## 关键发现：Edge 平台 JWT 配置

最新 Supabase 文档：<https://supabase.com/docs/guides/functions/auth>。

用户名登录发生在还没有 Supabase 用户 JWT 之前。**正式用户登录端点需要 `verify_jwt=false` 才能被未登录用户调用**；但这使端点对互联网上的请求可达，故绝对不能仅凭来源域名或公开 publishable key 授权操作。

必要的后端独立保护为：固定来源检查（仅减少浏览器跨域滥用，**不是可信身份凭证**）、Turnstile 服务端 `siteverify`（校验 hostname/action）、Token 单次使用原子 HMAC 限流、按用户名限流、密码经 Supabase Auth 校验、远端 UID 校验、专有 secret 服务端存储、限时开关。任何一项失败应拒绝，不得部分成功。

仅供未来**单独授权部署**时核对的示意配置（**未写到运行配置里**）：

```toml
[functions.mmh-n10-a740-username]
verify_jwt = false
```

不允许照抄示意配置后立即公开：必须先经完整的服务端安全审查、攻击测试、有效验证码及部署审批。需要单独检查生产 Supabase 所部署 Edge 的实际 JWT 检查设置，不能只看代码。

## 未完成的生产发布门槛

- **P0：用户名绑定入口不存在。** 目前 Edge 草案具有 `bind` 动作，但前端只有用户名登录，没有完整的经过邮箱验证账户的用户名绑定 UI。未绑定用户名的账户不能使用用户名登录。必须实现可访问的绑定流程并完成防重、防越权、同 UID 验证；不能通过手工在生产 DB 添加用户来代替产品功能。
- **P0：用户名直接注册尚未实现。** 当前模式是“邮箱已验证用户绑定用户名（alias）”而非“不需要邮箱的独立用户名账户”。用户原始需求中的后者属于 N10-B，需单独设计找回密码、防撞库、身份验证和设备验证。不得把现有 Email Sign Up 宣传为 Username Sign Up。
- **P0：后端仅有代码草案，未在生产部署，也没有生产 DB 表。** 生产用户名登录必须保持关闭。
- **P0：缺少完整生产隔离验证。** 需要用受控的专用测试用户检查创建/绑定/登录/Google UID 相符、跨 UID 账户/交易/习惯 RLS 拦截、撤销/退出及回滚。当前 mock 不等于生产验收。
- **P1：三处密码政策不同。** 正式邮件注册最少 6，邮件重置最少 10，App 设置中修改最少 8；用户希望新密码 6–20。不要通过限制“登录密码长度”误锁旧账户。必须先确认生产 Auth 策略，规划新建/重置/修改的一致性方案，避免降低既有安全强度或产生账号锁定。
- **P1：安全顾问旧提醒。** 生产 `mmh_delete_crypto_wallet_movement_v4` SECURITY DEFINER 可调用范围、泄露密码防护设置应独立复核。此次不修改这些内容。
- **P1：生产 secret 使用模式。** Edge 草案仍参照已验证 Staging 的旧式 `SUPABASE_ANON_KEY` / `SUPABASE_SERVICE_ROLE_KEY` 环境变量；后续需评估 Supabase 新 publishable/secret 密钥迁移，禁止把任何 service/secret 值写进浏览器、仓库或报告。
