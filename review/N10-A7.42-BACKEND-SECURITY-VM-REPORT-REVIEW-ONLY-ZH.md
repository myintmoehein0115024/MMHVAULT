## 2. Edge VM 模拟验证（不是在线生产验证）

通过以下 11 类隔离用例组：

1. 关闭开关：返回 503，且不进入外部登录或账号查询。
2. 不允许来源、不支持动作、错误用户名、超长请求：提前拒绝。
3. Cloudflare `siteverify` 失败、hostname 不符、action 不符：拒绝。
4. 同一个验证码 Token 再次使用：HMAC 原子限流拒绝。
5. 正常用户名登录：仅在 Auth 远端 UID 匹配时交接临时会话。
6. 密码错误：不向客户端返回 Token。
7. 密码正确但远端 UID 不符：拒绝、尝试撤销临时 proof。
8. 无用户名绑定或邮箱未验证：拒绝。
9. 未认证的绑定请求：拒绝且不尝试密码交换。
10. 已验证 UID + 当前密码绑定：成功；重复抢占已有用户名被拒绝；UID 不符无法绑定。
11. 连续 8 次失败密码尝试后的第 9 次：用户名桶限流，拒绝发起额外 Auth 密码校验。

测试中所有网络调用均为 Node 进程内桩函数；不会接触生产 Supabase、Cloudflare 或真实用户。限流测试仅模拟数据存储原子响应，**不是实际 PostgreSQL 并发与持久化验证**。

**P0：真正的注册方案仍未完成**：N10-A7 当前为已有邮箱确认账号的 username alias + password；用户要求的无需邮箱独立 username 注册与恢复属于 N10-B。不可宣传两者等同。

**P0：真实受控环境验收**：必须用隔离测试用户验证 Supabase Auth、Turnstile、PostgREST 函数权限、SQL 唯一性/并发、会话 UID、一人一名、跨 UID 财务 RLS 以及完整回滚。模拟验证不能替代。

**P0：公开 Edge 的 JWT 平台设置**：用户名登录开始时尚无用户 JWT，需按官方文档单独审查 `verify_jwt=false`，并确保 CAPTCHA、身份、配额等服务端核验完整。Origin/CORS 和 publishable key 均不是用户授权凭证。参考 <https://supabase.com/docs/guides/functions/auth-headers>。

**P1：限流抗滥用策略**：按用户名 8/15 分钟能减缓猜密，但也可能被恶意请求短时占用；上线前应评估按可信代理源/IP 等维度的额外频控、账号锁定恢复、失效限流表清理计划与监控告警，不能单靠 CORS。

**P1：密码政策**：邮箱注册至少 6 字符、邮箱恢复至少 10 字符，App 设置修改至少 8 字符；期望 6–20 字符，需结合现有 Supabase Auth 强密码策略统一新密码规则，同时**不能拦截旧账户的合法登录密码**。现有登录 128 字符上限只是请求保护，并不是“新密码上限”的最终政策。

**P1：生产 Supabase Advisor 已知旧项**：投资删除相关 SECURITY DEFINER 和泄漏密码防护，需要单独处理，不在此候选内擅改。
