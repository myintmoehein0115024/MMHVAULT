## 二、身份验证安全设计

运行时请求必须从允许的 `https://mmhvault.com` Origin、`POST application/json` 发送 `{"action":"configuration_health"}`，并提供 Supabase 登录用户的 `Authorization: Bearer <user_access_token>`。

管理员判断采用**两层在线检查**：

1. Edge `verify_jwt=true`；函数再用该 bearer JWT 调用 Supabase Auth `/auth/v1/user`，验证实际用户 UID，不接受浏览器自填 UID、任意邮箱或 `user_metadata`。
2. Edge 用**同一用户 JWT**调用原有 `public.mmh_is_admin()` RPC。该函数最终依据 `mmh_admin.members` 与 `auth.uid()` 作服务端成员校验。经数据库只读检查：管理员成员记录数为 1；该 RPC 对 `authenticated` 可用，对 `anon` 不可用。没有新增或修改管理员账户与权限。

只有在上述全部通过后，函数才返回裸 JSON **布尔值**：
- `true`：当前代码的 `configured()` 条件成立（项目地址匹配、必要环境变量存在且达到最低长度要求）。
- `false`：至少一项结构性配置要求不满足。**不指明是哪项，也不显示值**。

无身份或非管理员返回通用拒绝；依赖服务不可用则返回通用 503。**所有返回中均不包含 Secret 值、JWT、数据库记录、管理员列表或逐项配置状态。** 本阶段未提交、打印或读取私有 Secret。

**准确性界限：** `true` 只能确认配置变量存在及长度/URL 等结构要求，不能证明 Turnstile Secret 必然与 Cloudflare 匹配、HMAC 密钥熵足够，亦不等于用户登录路径已完成 E2E 验收。

## 四、真实双账户验收方案（仅准备，尚未获批执行）

**阶段 1：管理员配置检查。**
- 在已登录的真正管理员浏览器会话下，只经安全受控的 `mmhvault.com` 页面调用 `configuration_health`；JWT 只在本地浏览器传递给 Edge，不能贴到聊天、上传或截图。
- 期望 `200`、响应体为裸 `true`；收到 `false`、`403` 或 `503` 即停止推进，先定位配置问题。不得通过数据库或日志回显私钥。
- 因本轮工具没有管理员会话，所以该在线验收仍待完成。

**阶段 2：经另行明确批准后才可开始限时真实登录。**
- 测试账号 A 与 B 必须由账号所有者授权，不能让 AI 读取或保存密码、验证码、JWT、刷新 token。
- 生产 Edge 的公开用户名登录需要单独审批把 `verify_jwt` 设为 `false`，同时短时开放代码 gate 与 **最多 15 分钟**的 UTC 有效窗口；在独立受审版本中仅于指定时间生效。任何异常立即重新部署 `CODE_GATE_OPEN=false` 的安全基线。
- 使用正式 `mmhvault.com` 的 Turnstile Managed 公钥与服务端 Secret，验证码严格验证 hostname 与 action，并确认一次性使用与限流。
- A、B 分别用已有已确认邮箱账号绑定不同用户名（用户名唯一，UID 不变），确认两个账号互不串号；测试错误密码、冲突用户名、令牌重放、撤销、超窗、恢复旧密码失败以及退出后不再复用旧会话。
- 测试 Email/Password、Google OAuth 与回跳、邮箱恢复、现有账户 Session/UID 同一性。Google-only 账户必须先通过已验证邮箱设置密码，不能从 OAuth 凭证推算密码。
- RLS：优先测试只读访问已获授权的账户 A/B 现有安全测试资源；**禁止修改财务/Invest/Life Planner 的真实业务记录**；需要写入型跨 UID 漏洞测试时，必须另立批准的隔离测试 fixture/项目，不得借此触及真实个人资产。
- iPhone Safari、Android Chrome、桌面浏览器测试响应式中英双语、按钮失效/回滚与会话恢复。
- 闸门窗口到期即自动由代码 `boundedWindow()` 拒绝用户名操作，并须人工复核/重新部署全关闭版本；不得宣称自动化在后台永久运行。
