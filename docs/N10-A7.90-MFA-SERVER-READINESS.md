# N10-A7.90 — MFA Server Readiness (2026-10-30)

**Status: audit/rollout hold, not an MFA launch.**

## Read-only audit
- `auth.mfa_factors` returned no rows at inspection time. This is a snapshot only.
- Existing finance-table RLS guards access using `auth.uid() = user_id` but does not require AAL2 when a user has verified TOTP.
- Current login and app frontend checks alone cannot prevent an AAL1 client from querying the finance API directly.
- No production RLS, financial data, account UID, auth settings, recovery verifier or existing factor was modified.

## Temporary release guard
New authenticator enrollment in Settings is disabled by `N10A790_TOTP_ENROLLMENT_RELEASED=false` until backend security and recovery acceptance. Verified factor management and TOTP sign-in checks remain in code. This UI flag is not server-side enforcement.

1. Inventory tables, views, SECURITY DEFINER RPCs, Storage, Edge Functions and realtime financial data surfaces.
2. Stage conditional MFA-enrolled-account AAL2 authorization on server while preserving ordinary AAL1 account access. Review every dependency and test rollback.
3. Establish secure recovery after lost authenticator device and verify second-factor recovery cannot be bypassed with permanent ten-word credentials.
4. Run full tests: email+password, username+password, Google OAuth, ten-word recovery; AAL1 denied and AAL2 allowed for enrolled accounts; no-factor AAL1 still allowed.
5. Test session expiry, refresh, sign-out, duplicate factor, wrong code, device change, Google UID linking, factor unenrollment, account switching and failure handling.
6. Re-enable enrollment only after evidenced staging and production rollout checks.
